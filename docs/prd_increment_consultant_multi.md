## 1. 增量需求

### 1.1 原始需求

> 用户原文：「好的，现在让我们在责任人右边增加一列，叫"顾问人"，同时责任人和顾问人应该允许不止一个人」

两条诉求：

1. **新增列**：「顾问人」紧挨「负责人」右侧。
2. **支持多人**：负责人与顾问人都允许填写多个姓名（原负责人只允许一个字符串）。

### 1.2 需裁定的两个设计点（用户已裁定）

| # | 问题 | 用户裁定 | 影响 |
| --- | --- | --- | --- |
| Q1 | 「顾问人」在 MS Project 导出（MSPDI）里怎么表达？ | **作为 Notes，不计入 Resource** | MSPDI 只给负责人生成 `Resource` / `Assignment`；顾问人降级为任务备注行 `顾问人：A、B`。CSV 仍单列输出 |
| Q2 | 多人怎么录入？ | **可搜索多选下拉** | MUI `Autocomplete` 开 `multiple` + `freeSolo`，v1.2.0 起候选来自当前工作区邀请成员（邀请制）+ 本计划内已用过的名单外姓名 |

### 1.3 不在本次范围

- 不改名单来源（`shared/roster.ts` 仍是唯一真源，21 人，含 User14 在 User13 之后）
- 不做「按人员筛选 / 分组 / 负载视图」（见 BACKLOG P2）
- 不动甘特图任务条的人员渲染规则（仍只显示负责人，多人用顿号拼接）
- 不做 `schemaVersion` 升级（保持 1，用归一化完成迁移）

## 2. 行为细则

### 2.1 数据模型（P0-1）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `Task.owner` | `string[]` | 由 `string` 升级。历史单人值（含手打的 `"User01,User13"`）经 `normalizePlan()` 自动拆成数组 |
| `Task.consultant` | `string[]` | 新增。旧计划无此字段 → 归一化补 `[]` |

**迁移策略（不写迁移脚本）**：归一化即迁移。`normalizePlan()` 是前后端共用的唯一入口，读入历史计划时把字符串包成数组，保存写回即完成升级。磁盘上 4 个既有计划的 owner 实测仍为字符串（`User05` / `User04` / `User06` / `user14`），打开后直接以数组形态显示，用户保存后才落盘为数组。

### 2.2 人员值归一化（`shared/people.ts`，P0-2）

| 规则 | 行为 |
| --- | --- |
| trim | 去掉首尾空白 |
| 去空 | 空串项丢弃 |
| 拆分 | 字符串按 `, ， 、 ; ； | /` 拆分（**不拆含空格的姓名**，如 `Group A`） |
| 去重 | 大小写不敏感（`User01` 与 `user01` 视为同一人），**保留首次出现的写法** |
| 脏数据 | `null` / 数字 / 对象 / 布尔 → 降级为 `[]` |
| 展示 | 顿号 `、` 拼接（**不能用逗号**，会撑出额外 CSV 列） |

### 2.3 表格与录入（P0-3）

| 行为 | 期望 |
| --- | --- |
| 列序 | `… 依赖 → 负责人 → 顾问人 → 操作`（9 列） |
| 默认列宽 | 两列均 120px（min 90 / max 360） |
| 只读态 | 显示 `A、B`；空显示灰色 `—`；hover 有 tooltip 提示「点击设置负责人（当前：…）」 |
| 进入编辑 | 单击单元格；编辑态是**绝对定位浮层**（min 248 / max 420 / max-height 104 可滚），**不占文档流 → 行高恒 32px** |
| 连选 | 选中一人后下拉不关闭，可继续点选（`disableCloseOnSelect`） |
| 取消 | 再点一次已选项即取消（选项左侧显示 `✓`） |
| 自由输入 | 输入名单外姓名回车即新增，选项显示「添加 "xxx"」 |
| 落库时机 | 每次增删**立即提交** store，不依赖失焦 |
| Esc | 关闭编辑器（已选保留） |
| 失焦 | 输入框里的残字补成一个人后关闭 |
| 候选名单 | 负责人与顾问人共用一份：内置 21 人（原序）+ 本计划内已用过的名单外姓名 |
| 行高 | 编辑中 / 选多人后恒为 **32px**（K16，与甘特条严格对齐） |

### 2.4 导出（P0-4）

| 目标 | 负责人 | 顾问人 |
| --- | --- | --- |
| MSPDI `<Resource>` / `<Assignment>` | 每人一条（多人 → 多条 Assignment） | **不生成**（用户裁定 Q1） |
| MSPDI `<Notes>` | — | 追加一行 `顾问人：A、B`；原有备注保留，两者用换行分隔 |
| CSV | 「负责人」列，顿号拼接 | 新增「顾问人」列（表头 12 → 13 项），顿号拼接 |

### 2.5 导入（P0-5）

MPP 导入时单个资源名 → 包成单元素数组 `[name]`；无资源 → `[]`（不再是 `undefined`）。顾问人恒为 `[]`。

### 2.6 列宽存储升级 v2 → v3（P0-6）

| 项 | v2（旧） | v3（新） |
| --- | --- | --- |
| 落盘形态 | `[52,465,…,136]` 按下标数组 | `{"seq":52,"name":465,…}` 按列名对象 |
| 存储键 | `plan-gantt:colw:v2:<planId>` | `plan-gantt:colw:v3:<planId>` |
| 迁移 | — | v3 本计划键 → v2 本计划键 → v1 全局键 → 默认值；**迁移只读不写** |
| 历史列序 | — | `LEGACY_LAYOUT` 常量固化 v1/v2 时代的 8 列顺序，作为迁移的解释依据（历史事实，将来增删列都不要改） |
