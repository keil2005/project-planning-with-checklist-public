## 1. 原始需求复述

1. 用户名单**写死在 app 内**，按严格顺序 20 人：
   `User01, User02, User03, User04, User05, User06, User07, User08, User09, User10, User11, User12, User13, User15, User16, User17, User18, Group A, Group B, External`
   （大小写与空格保持原样，`Group A` / `Group B` 含空格。）
2. 该名单同时作为**每个任务的 Assignee（负责人）候选来源** → 任务新增 Assignee 字段。
3. Assignee 录入方式：**不是纯下拉**，而是「输入后匹配联想下拉」；**同时支持手动添加名单之外的人**（自由文本）。
4. 启动选身份仍使用这份名单（即写死后的名单；**2026-09-01 起为 21 人**，见「变更记录」）。

## 3. 产品目标

1. **名单唯一且有序**：全 app 人员候选来自唯一写死真源，顺序与用户给定完全一致，杜绝多处名单不一致。
2. **责任到人**：每个任务可标注负责人，并随导出物一起流转到 MS Project / Excel。
3. **录入不设限**：名单内快速联想选中，名单外可自由手填，不因名单缺人而阻断录入。

## 4. 用户故事

- **US-1（启动选人）**：作为计划编辑者，我希望启动时从写死的名单（现 21 人）里按熟悉的既定顺序选自己的身份，这样我不必再维护 `users.json`，且各机器上看到的名单完全一致。
- **US-2（联想填负责人）**：作为计划编辑者，我希望在任务的「负责人」单元格里打几个字母就能联想出名单中的候选并回车填入，这样录 20 行任务时不用每次翻完整下拉。
- **US-3（名单外手填）**：作为计划编辑者，当负责人是外部供应商联系人等名单外人员时，我希望直接手敲姓名并确认保存，这样不必为一次性人员改代码名单。
- **US-4（导出带责任人）**：作为项目汇报者，我希望导出的 MS Project XML / CSV 及甘特条上都能看到每个任务的负责人，这样汇报和分派无需二次人工补录。

## 6. UI 交互稿（文字描述）

### 6.1 任务表格「负责人」列

**列位置与尺寸**
- 插入位置：**「依赖」列之后、「操作」列之前**（保持左侧时间相关列的既有阅读顺序不被打断）。
- 列宽建议 `120px`；`GRID_COLUMNS` 变为 8 列：`52px minmax(160px,1fr) 96px 96px 78px 110px 120px 136px`；`MIN_TABLE_WIDTH` 730 → **850**。
- 表头文案：`负责人`。
- 行高**必须**仍为 `ROW_H = 32`（与右侧甘特图行对齐，见既有约束 K16）；联想下拉以浮层（popper）呈现，**不得**改变行高或撑开表格。

**单元格交互流程**
1. **只读态**：显示负责人文本；为空时显示浅灰占位（如 `—` 或空白）；未持有编辑锁时不可进入编辑（与其他列一致）。
2. **进入编辑**：点击/聚焦单元格 → 变为输入框，光标就位，原值全选（便于直接覆写）。
3. **输入联想**：
   - 输入为空时：下拉展示**完整 21 人名单，顺序为名单原序**（相当于免费获得「下拉选择」能力）。
   - 输入非空时：从名单过滤出**包含**该输入的候选（大小写不敏感、子串匹配），候选中匹配片段**高亮**；候选顺序仍沿用名单原序，不做模糊分数重排。
   - 示例：输入 `oth` → 命中 `Group A`、`Group B`；输入 `ka` → 命中 `User08`；输入 `k` → 命中 `User01`、`User07`、`User08`（按名单序）。
4. **选中填入**：`↑/↓` 移动高亮项，`Enter` 或鼠标点选 → 填入该候选并退出编辑。
5. **手填确认（名单外）**：输入内容无任何候选命中时，下拉显示一条提示型选项（如 `使用 "张三"`）；`Enter` 或失焦 → 以自由文本确认保存，**不报错、不回滚**。
6. **取消**：`Esc` 放弃本次编辑，恢复原值。
7. **清空**：全选删除后确认 → 负责人置空（合法状态）。
8. **归一化**：确认时 **trim 首尾空白**；**保留中间空格**（`Group A` 必须原样保留）；**不做**大小写归一（手填 `user01` 就存 `user01`，不自动纠正为 `User01`）。

### 6.2 启动选人页（UserGateDialog）

- 标题与说明沿用现状，但说明文案中「名单来自 `config/users.json`」**需改为**「名单为系统内置」（避免误导运维去改文件）。
- 候选列表 = 内置 21 人，**按名单原序**从上到下渲染；当前已选身份保持高亮（现有 `selected` 逻辑不变）。
- 列表高度受限时可滚动；建议顶部加过滤输入框（P1-4）。
- **此处不提供自由文本输入**：启动身份必须是名单内成员（见 Q1）。
- 原「未读取到用户名单」的 warning 分支在名单写死后成为**不可达状态**，可移除或降级为兜底。

### 6.3 甘特图（P1-3）

- 在任务条右侧（条尾外 4~6px）以 11px 灰色文字渲染负责人；为空则不渲染。
- `day` / `week` 档显示，`month` 档隐藏（避免密集重叠）。
