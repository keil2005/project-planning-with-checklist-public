## 1. 原始需求复述 + 已确认前提

### 1.1 用户原话（本次需求）
「关于节假日（默认非工作日），让我们参考中国日历，主要非工作日可以用颜色体现（甘特图中），输入时表格时则以弹窗提示，表示要求确认。最终的非工作日全部由用户在非工作日设置中确定和设定」

### 1.2 主理人已与用户确认的 4 项决策（直接作为前提，不要再问）
1. **排程口径：非工作日参与工期计算** —— 工期只计工作日，排程自动跳过周末与节假日（真正的工作日历，对齐 MS Project 习惯）。这是本次最重的改动点。
2. **日历数据源：内置中国法定节假日表 + 调休补班日** —— 代码内写死（内部服务器可能无外网），默认周六日为非工作日；**调休补班的周末（如某周六要上班）必须能覆盖周末默认变成工作日**。用户可在设置里增删覆盖。
3. **表格输入弹窗行为：确认保留 或 顺延到下一个工作日** —— 用户在表格输入的开始/结束日期落在非工作日时弹窗提示（如「2026-10-01 是国庆假期」），提供两个操作：「仍使用该日期」/「顺延到下一个工作日」。不强制、不禁止。
4. **设置作用域：全局共享** —— 一份非工作日配置，所有计划共用，存在服务器 DATA_DIR 根目录；任一用户修改后对所有人生效。

## 6. 核心口径结论（★ 本次 PRD 核心价值，架构师据此编码）

> 统一前置定义：**有效工作日历 `WorkCalendar`** = 内置周末规则（Sat/Sun 非工作）∪ 内置法定节假日 ∪ 用户增删覆盖 − 调休补班日（补班覆盖周末使其变工作）。`WorkCalendar` 由全局配置在 server/前端构建为**高效查询结构**（如 `Set<ISODate>` + `isWorking(date)`），以参数形式注入 `shared` 纯函数，**`shared` 不直接读文件**。

### Q1：`d / w / m` 在工作日历下的口径

**结论（全部对齐 MS Project 默认工作日历）：**
- **`5d` = 5 个工作日**。毫无疑问。
- **`1w` = 5 个工作日**（MS Project 默认：一周工期 = 日历中一周的工作日数，标准 5 天）。即 `w` 单位 = `5 × value` 个工作日。这与 `5d` 同口径，仅粒度不同（如 `2w` = 10 个工作日）。
- **`1m` = 保留自然月 ENDPOINT 语义**（`add(1,'month')` + dayjs 月末夹取，结果与现状逐字一致，如 `2026-08-26 + 1m = 2026-09-26`），但其起止跨度内的「工期」按工作日计（与 `d/w` 一致）；`end` 是否落在非工作日按 Q3 规则（允许落在非工作日，作为排他边界）。

**理由：**
1. `d/w` 改为工作日计数是决策 1 的直接要求（工期只计工作日）。
2. `1w=5` 工作日与 MS Project 完全一致，避免「1 周 ≠ 5 工作日」的认知冲突。
3. `m` 保留自然月可**零破坏既有已存计划**：旧计划用 `1m` 的仍得到 `2026-09-26` 这一端点，仅工期标签按工作日重算，不会因启用工作日历而整体平移（对比 `d/w` 会因跳过周末而平移，见 Q5）。

**运算契约（供 `datetime.ts` 实现）：**
- `addDuration(S, {N,'d'})`：从 `S`（含）起数第 N 个工作日，返回 = 第 N 个工作日 `+ 1` 自然日（即排他 `end`）。
- `addDuration(S, {N,'w'})`：等价 `addDuration(S, {5N,'d'})`。
- `addDuration(S, {N,'m'})`：保持 `S.add(N,'month')`（自然月，不受日历影响），`end` 允许落非工作日。
- `subDuration(E, {N,'d'|'w'})`：`addDuration(E, {N,unit}, -1)`，对称可逆向。
- `diffDuration(start, end)`：**优先级 m > w > d 不变**；`w` 分支（`days%7==0`）仍返回「周数」，故「5 工作日跨 7 自然日」的跨度会显示为 `1w`，与输入一致；`m` 分支（`addMonths==end`）仍返回「月」，保留 `1m` 标签。

**既存计划影响**：`d/w` 单位会因跳过周末而**重算平移**（如 `5d` 原结束周一→现结束周二）；`m` 单位端点不变。详见 Q5。

### Q2：依赖 lag 偏移口径（`3FF+1w` 的 `+1w`）
**结论：lag 与 Q1 完全一致——`d/w` 按工作日、`m` 按自然月，全部走工作日历。** 不引入「elapsed（自然日）」特殊单位（MS Project 用 `e` 前缀表示 elapsed，本期不支持）。

**理由**：与 Q1 同口径，且 `lagToDays(anchor, lag, sign) = diffDays(anchor, addDuration(anchor, lag, sign))` 现已天然得到「锚点→锚点+lag」的**实际自然日跨度**（含被跳过的周末），导出 MSPDI 的 `LinkLag`（自然日×480×10）因此更准确，与 Project 工作日历一致。

**验收**：`3FF+1w`，pred FF `end`=某周五 → succ `end` = 周五 + 5 工作日（下一周五）。`lagToDays` 返回 7 自然日。

### Q3：ENDPOINT 半开区间 `[start, end)` 在工作日历下的行为
**结论：`end` 是排他边界，允许落在非工作日；`end = 第 N 个工作日 + 1 自然日`（见 Q1）。不把 `end` 强制顺延到工作日。**

**示例**：周五开始、`1d` 工期 → `start=Fri`，`end=Sat`（排他，仅覆盖周五一列）。`Mon + 5d` → `end=Sat`（覆盖 Mon–Fri）。`Tue + 5d`（跨周末）→ `end=下周二`（覆盖 Tue~Mon 共 7 自然日，周末列着色但任务条跨越其上，符合「5 工作日 = 7 自然日」直觉）。

**两条基线优势仍成立（已验证）：**
- **甘特条无缝衔接**：沿用 `[start, end)` 半开，条宽 `x(end)-x(start)`，工作日相邻任务天然相接；周末以着色列呈现间隙，视觉正确。
- **FS 依赖无「差一天」bug**：`succ.start ≥ pred.end + lag`，`pred.end` 为排他边界（可能 Sat），配合 **Q4 的 start 自动顺延**（succ 计算出的 start 落非工作日则顺延到下一工作日），链路不差一天。例：`A 5d` 周一→`end=Sat`；`B FS` → `B.start = Sat` 顺延为 `Mon`，正确（A 占满工作日，B 下周一开始）。

**验收**：断言 `Mon+5d` 的 `end == Mon+5` 自然日（即周六）；`Fri+1d` 的 `end == 周六`；FS 链 `A.end=Sat` → `B.start` 经顺延后为周一。

### Q4：任务开始日落在非工作日（两条链路分别定义）
**结论：分两条链路。**
1. **排程推算出的 start/end（依赖/锚点驱动）落非工作日 → 自动顺延到下一个工作日，无弹窗。** 这是工作日历的应有行为（`anchor`/`cs` 求出后若为非工作日，取 `nextWorkingDay`）。`end` 按 Q3 允许为排他非工作日，故**仅 start 需要顺延**（end 不需）。
2. **用户手动输入 start/end 落非工作日 → 弹窗（决策 3 / P0-4）**：提供「仍使用该日期」（按原值落 `input`，用户显式覆盖）或「顺延到下一个工作日」（存入下一工作日）。弹窗为 UI 确认，不产生 Diagnostic、不阻断保存。

**验收**：仅 `anchor` 约束的任务，若 `anchor` 为周六 → `start` 顺延周一（无弹窗）；用户在表格手填 `start=2026-10-01`（国庆）→ 弹窗出现；选「顺延」→ `input.start=2026-10-08`（国庆后首个工作日的下一工作日，依实际补班而定）；选「仍使用」→ `input.start=2026-10-01` 原值。

### Q5：已有计划的兼容 / 迁移
**结论（内部小范围、存量极少，选简单方案）：启用全局工作日历，实时重算 + 打开横幅提示，不保留旧日历标记。**
- 全局工作日历常驻；`normalizePlan` 将 `plan.calendar.mode` 强制为 `'WORKWEEK5'`。
- 旧计划（`mode=='NATURAL'`）重新打开时，因 `computed` 每次全量重算 → 日期已按新规则变化；前端检测 `mode!='WORKWEEK5'` → 显示 P0-8 信息横幅，提示用户核对后保存固化（无需强制重算/无需 notes 流程，普通保存即落新值）。
- **不引入 per-plan 旧日历标记**（避免复杂度与迁移脚本）。存量少、用户可接受平移。

**验收**：打开一个 v1.0/v1.1 时期保存的计划 → 顶部出现工作日历提示横幅；其 `5d` 任务结束日已从原自然日平移到工作日；保存后 `mode` 变为 `WORKWEEK5`，横幅不再出现。

### Q6：内置节假日表的年份覆盖与降级
**结论：内置覆盖 2026、2027（当前系统日期 2026-08）；超出范围的年份 → 仅周末规则 + 横幅提示补录（P1-1）。**
- 内置数据放 `shared/china-holidays.ts`：`BUILTIN_HOLIDAYS: Record<number, ISODate[]>` 与 `BUILTIN_MAKEUP: Record<number, ISODate[]>`（2026、2027）。
- server 启动：若 `DATA_DIR/calendar.json` 不存在 → 用内置种子初始化（含 `userAdded`/`userRemoved` 空、`makeup` 初始=内置补班）。
- 计划日期年份不在 {2026,2027} → 该年份仅按周末规则排程，触发 P1-1 横幅。

**⚠ 数据准确性门禁（P0 验收硬条件）**：内置具体日期**必须以国务院办公厅发布的年度安排为准**。PRD 给出数据结构与覆盖年份；**确切日期由架构师/开发对照官方公报填入 `shared/china-holidays.ts`**，并在「非工作日设置」中可修正（无需重新部署）。下表为结构示例（稳定锚点，变量项标 ⚠ 待核对）：

| 年份 | 法定节假日（非工作，示例/待核对） | 调休补班（周末变工作，示例/待核对） |
| --- | --- | --- |
| 2026 | 元旦 01-01；春节 ⚠（约 02-15~02-22，含除夕）；清明 ⚠（约 04-04~04-06）；劳动 ⚠（约 05-01~05-05）；端午 ⚠（约 06-19~06-21）；中秋 ⚠（约 09-25~09-27）；国庆 10-01~10-07 | ⚠ 依国务院公报（如春节/劳动/国庆前后的补班周六） |
| 2027 | ⚠ 同上结构，待公报发布后填入 | ⚠ 待公报 |

> 说明：元旦(01-01)、国庆(10-01~10-07) 为稳定锚点；春节/清明/劳动/端午/中秋及补班日期每年浮动，**严禁凭记忆硬编码**，必须核对官方公报后再落地。

### Q7：非工作日设置的编辑权限与审计
**结论（对齐基线强审计取向 K13 append-only）：**
- **编辑权限**：复用 `LockService`，以保留资源 id `GLOBAL_CALENDAR` 占用全局锁（与计划编辑体验一致，防止两人同时改互相覆盖）。未持锁 → 设置对话框「保存」禁用并提示「他人正在编辑日历配置」。
- **变更纪要 / 审计**：每次保存**必须 append `DATA_DIR/calendar-history.json`**（独立文件，不混入任何 plan 的历史），记录 `editor` + `timestamp` + `变更摘要`（如「新增 2026-05-08 自定义假期 / 取消 2026-02-16 春节 / 标记 2026-10-10 补班」）。摘要由前端根据本次 diff 生成。
- **版本历史 / 回滚**：`calendar-history.json` append-only；支持「回滚到上一版」（回滚 = 以旧配置为新版本追加，不删不改旧记录，P1-3）。
- **设计取向理由**：基线编辑锁与版本历史都是 per-plan 的，全局配置不属于任何 plan，故用**独立文件 + 独立保留资源锁**，既延续「谁改的/可回溯」的审计文化，又不污染计划历史。

**验收**：未持全局锁时设置保存被拒（409 类行为）；持锁保存后 `calendar.json` 更新且 `calendar-history.json` 多一条带 editor/时间的记录；回滚后配置回到旧版且历史不丢。

## 7. UI 交互稿（文字描述）

### 7.1 甘特图非工作日着色（C7 / P0-3）
- **周末底纹**：沿用浅灰（`COLOR.weekend`，建议提为 CSS 变量 `--gantt-weekend` 以适配主题）；周六、周日列着色。
- **法定节假日底纹**：**不同色**（建议浅红/粉，如 `--gantt-holiday: #fde8e8` / dark 下 `#3f1f1f`），与周末明显区分；覆盖 `_year ∈ {2026,2027}` 且日期在内置/自定义节假日集合。
- **调休补班日**：若某周六/日属于补班集合 → **不着色**（视同工作日），与周末底纹区分。
- **渲染位置**：复用 `axis.ticks` 的 `weekend` 标记扩展为 `nonWorking`/`holiday` 三态；`dayWidth>=10`（日档）绘制整列底纹（与现有周末底纹同层）。
- **主题**：颜色经 MUI 主题或 CSS 变量取色，dark/light 下均可辨；不得写死仅适配 light。
- **图例（底部）**新增/更新：① 任务 ② 父任务汇总 ③ 依赖冲突 ④ **周末（浅灰）** ⑤ **法定节假日（红调）**；并注明「调休补班日不着色」。

### 7.2 表格输入弹窗（C8/C9 / P0-4 / 决策 3）
- **触发**：`TaskTable` 的「开始」「结束」`CellInput` 在 `onBlur` 提交时，若该日期 `isWorking()==false` 且用户本次未选择「不再提示」（P2-1 才做）→ 弹出确认框（不阻塞输入落库，由用户二选一决定最终值）。
- **文案**：标题「日期落在非工作日」；正文「**{YYYY-MM-DD} 是{假期名 / 周末}，非工作日。**是否仍使用该日期？」；假期名来自日历配置（如「国庆」），周末显示「周末」。
- **两个按钮**：
  - 「仍使用该日期」→ 按用户原输入落 `input.start/end`（用户显式覆盖，排程照常；若该 start 参与依赖则按 Q4 链路线：手动输入不自动顺延，仅推算链顺延）。
  - 「顺延到下一个工作日」→ 将日期替换为 `nextWorkingDay(原日期)` 后落库。
- **「本次不再提示」**：本期**不做**（见 P2-1）；避免用户误关安全网导致静默漂移。

### 7.3 非工作日设置对话框（C9 / P0-5 / Q7）
- **入口**：Toolbar 新增「非工作日设置」按钮（持有计划编辑权或全局锁均可打开查看；保存需全局锁）。风格对齐现有 `Dialogs.tsx`（MUI `Dialog` + `DialogTitle/Content/Actions`）。
- **布局**：
  - 顶部：年份切换（`2026` / `2027` / 其它）→ 切年重绘月历。
  - 中部：**月历网格**（12 月或当前月，建议可滚动的整年网格），每格显示日期数字 + 状态标：
    - 周末：灰底；
    - 法定节假日：红调底 + 「法定」小标（来自内置）；
    - 自定义假期：另一色底（如橙调）+ 「自定义」小标 + 右上「×」删除；
    - 补班日（周末变工作）：蓝调底 + 「班」标，可点回退为普通周末；
    - 普通工作日：白底。
  - 点选交互：点普通工作日 → 加为自定义非工作日；点内置法定节假日 → 弹「取消该法定日」（用户覆盖）；点周末 → 切为补班（工作）；点自定义/补班 → 取消恢复默认。所有改动先存内存草稿。
  - 底部：摘要「本年非工作日 N 天（法定 M / 自定义 K），调休补班 L 天」+ 「重置为内置默认」按钮（清空 `userAdded/userRemoved/makeup` 回内置）+ 「取消」「保存」。
- **保存**：需持有全局锁；写入 `DATA_DIR/calendar.json`；append `calendar-history.json`（editor+时间+摘要）；保存后**所有计划实时生效**（前端刷新内存中的 `WorkCalendar`，触发 `recompute`）。
- **区分内置/自定义/补班**：如上以底色调 + 文字标区分；「重置为内置默认」仅清用户覆盖，不动内置数据。
